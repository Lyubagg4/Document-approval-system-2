# Система согласования документов

Консольное приложение для управления процессом согласования документов:
система проверяет данные документа, контролирует срок согласования,
проверяет возможность согласования и позволяет вынести решение.

## Назначение

Приложение управляет процессом согласования документов в организации.
Оно позволяет учитывать документы и их авторов, фиксировать решения
согласующих, проверять сроки и формировать итоговые статусы документов.

## Целевая аудитория

Сотрудники организаций:
- авторы документов (юристы, бухгалтеры, менеджеры);
- руководители-согласующие;
- администраторы документооборота.

## Предметная область

Электронный документооборот: документы, авторы, согласующие, статусы,
сроки согласования, решения и комментарии.

Основные объекты предметной области:
- **документ** — название, тип, автор, срок согласования, статус;
- **пользователь** — ФИО, подразделение, должность, email;
- **согласование** — документ, согласующий, решение, комментарий, дата,
  признак отмены.

Правила предметной области:
- один документ может иметь только одно активное согласование;
- автор документа не может согласовать собственный документ;
- срок согласования документа не должен быть истёк;
- отменённое согласование не блокирует документ — на него можно создать
  новое согласование;
- статус документа вычисляется по его согласованиям: «approved»,
  «rejected» или «pending».

## Основные сущности

### `Document` — документ

Объект `Document` представляет документ, проходящий согласование.

Основные атрибуты:
- `id` — уникальный идентификатор документа;
- `title` — название документа;
- `doc_type` — тип документа;
- `author_id` — идентификатор автора документа;
- `deadline` — крайний срок согласования.

Основные методы:
- `is_suitable_for(current_date)` — проверка истечения срока согласования
  (в коде — `is_overdue`);
- `get_status(approvals)` — определение кода статуса документа;
- `get_status_label(approvals)` — текстовое представление статуса;
- `__str__()` — строковое представление документа;
- `from_data(data)` — создание объекта из словаря (classmethod);
- `to_dict()` — преобразование в словарь для JSON;
- `validate_title(title)` — проверка названия (staticmethod).

### `User` — пользователь

Объект `User` представляет сотрудника организации.

Основные атрибуты:
- `id` — идентификатор пользователя;
- `name` — ФИО;
- `department` — подразделение;
- `role` — должность;
- `email` — адрес электронной почты.

Основные методы:
- `__str__()` — строковое представление пользователя;
- `from_data(data)` — создание из словаря (classmethod);
- `to_dict()` — преобразование в словарь.

### `Approval` — согласование

Объект `Approval` представляет согласование документа пользователем.

Основные атрибуты:
- `id` — идентификатор согласования;
- `document_id` — идентификатор документа;
- `user_id` — идентификатор согласующего;
- `decision` — решение: «approved», «rejected» или «pending»;
- `comment` — текст комментария;
- `approval_date` — дата согласования;
- `is_cancelled` — признак отмены согласования.

Основные методы:
- `cancel()` — отменить согласование (меняет флаг `is_cancelled`);
- `__str__()` — строковое представление согласования;
- `from_data(data)` — создание из словаря (classmethod);
- `to_dict()` — преобразование в словарь.

## Основные операции

### Работа с документами
- добавление документа;
- поиск документов по подстроке названия;
- поиск документа по идентификатору;
- фильтрация документов по типу;
- сортировка документов по сроку согласования;
- просмотр списка документов.

### Работа с пользователями
- добавление пользователя;
- поиск пользователя по подстроке ФИО или email;
- просмотр списка пользователей.

### Работа с согласованиями
- проверка возможности согласования (правила автора, срока, дубля);
- создание согласования;
- отмена согласования;
- просмотр списка согласований;
- определение текущего статуса документа.

## Хранение данных

Данные приложения хранятся в каталоге `data/`:
- `data/documents.json` — документы;
- `data/users.json` — пользователи;
- `data/approvals.json` — согласования.

При загрузке данные JSON преобразуются в объекты `Document`, `User` и
`Approval`. При сохранении объекты преобразуются обратно в данные JSON.

В `approvals.json` хранятся идентификаторы связанных объектов
(`document_id`, `user_id`), а не сами объекты. Связи восстанавливаются
при загрузке.

## Назначение модулей

### `main.py`
Точка входа в приложение. Отвечает за:
- запуск приложения;
- отображение главного меню;
- получение данных от пользователя;
- организацию пользовательских сценариев;
- загрузку и сохранение данных через `storage.py`.

### `models/documents.py`
Содержит класс `Document` и функции работы с коллекцией документов:
`add_document()`, `find_document()`, `find_document_by_id()`,
`filter_documents_by_type()`, `sort_documents_by_deadline()`,
`show_documents()`.

### `models/users.py`
Содержит класс `User` и функции работы с пользователями:
`add_user()`, `find_user()`, `find_user_by_id()`, `show_users()`.

### `models/approvals.py`
Содержит класс `Approval` и функции работы с согласованиями:
`can_approve_document()`, `is_document_open_for_approval()`,
`create_approval()`, `cancel_approval()`, `find_approval_by_id()`,
`get_approval_status()`, `show_approvals()`.

### `storage.py`
Отвечает за загрузку и сохранение данных. Выполняет преобразование:
- JSON → объекты Python;
- объекты Python → JSON.

### `utils.py`
Содержит вспомогательные функции безопасного ввода:
- `input_int()` — безопасный ввод целого числа;
- `input_date()` — безопасный ввод даты в формате ДД.ММ.ГГГГ;
- `input_str()` — безопасный ввод непустой строки.

### `tests/`
Содержит автоматизированные тесты pytest:
- `test_documents.py` — тесты класса `Document`;
- `test_users.py` — тесты класса `User`;
- `test_approvals.py` — тесты класса `Approval` и функций согласований.

## Требования

- Python 3.10+;
- pytest >= 8.0;
- flake8 >= 7.0.

pip install -r requirements.txt

## Запуск тестов

```bash
pytest -v
```

Тесты проверяют:
- создание и работу объектов `Document`, `User` и `Approval`;
- методы классов;
- операции с документами;
- создание и отмену согласований;
- связь согласования с документом и пользователем;
- правила доступности документа для согласования.

Исходный код проекта хранится в Git-репозитории. История изменений
отражает три этапа разработки:

- `PR2` — переход к коллекциям, функциям, модулям, JSON и тестам;

  на классах `Document`, `User` и `Approval`.
