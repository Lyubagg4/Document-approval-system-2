## Этап PR1 — начальный сценарий

**Тег в Git:** `pr1` (коммит `01a4632`).

В исходном `main.py` был реализован один законченный сценарий предметной
области: проверка возможности согласования документа и вынесение
решения. Использовались только базовые конструкции Python:
- простые типы данных (строки, целые числа, даты);
- операции и преобразование типов;
- условные конструкции `if/elif/else`;
- функции с параметрами и возвращаемыми значениями;
- импорт модуля `datetime`.

Реализованы 5 функций:
| Функция | Назначение |
|---|---|
| `get_status_label(status)` | Возвращает название статуса документа. |
| `check_document_data(title, author, approver)` | Проверяет, заполнены ли данные документа. |
| `check_deadline(current_date, deadline)` | Проверяет, не истёк ли срок согласования. |
| `can_approve_document(author, approver)` | Проверяет правило «автор не согласующий». |
| `make_decision(decision_code, comment)` | Формирует результат согласования. |

Структура на момент PR1:
```
document_approval/
├── README.md       # описание проекта
├── .gitignore      # настройки Git
└── main.py         # начальный сценарий
```

## Этап PR2 — модульная структура, JSON, тесты

**Тег в Git:** `pr2` (коммит `ef3c7cf`).

Начальный сценарий ПР1 переработан в функциональное приложение,
работающее с множеством документов, пользователей и согласований.

### Что добавлено

**Коллекции данных:**
- `dict[int, dict]` для документов и пользователей — ключом служит
  идентификатор, значением — словарь с данными;
- `list[dict]` для согласований — упорядоченный список словарей.

**Модульная структура (5 модулей):**
| Модуль | Назначение |
|---|---|
| `documents.py` | Функции работы с документами: добавление, поиск, сортировка, проверка срока, вывод списка. |
| `users.py` | Функции работы с пользователями: добавление, поиск, вывод списка. |
| `approvals.py` | Функции согласований: проверка возможности, создание, отмена, вывод статуса. Функция `get_approval_status()` перенесена из ПР1. |
| `storage.py` | Загрузка и сохранение JSON-файлов через контекстный менеджер `with`. |
| `utils.py` | Безопасный ввод: `input_int()`, `input_date()`, `input_str()`. |
| `main.py` | Точка запуска: меню и вызов функций. |

**Обработка исключений:**
- `FileNotFoundError` и `JSONDecodeError` в `storage._load_json()` —
  программа не завершается аварийно при отсутствии или повреждении
  файла, возвращает пустой список;
- `ValueError` в `utils.input_int()` и `utils.input_date()` —
  при некорректном вводе запрос повторяется.

**Хранение данных в JSON:**
- `data/documents.json` — список документов;
- `data/users.json` — список пользователей;
- `data/approvals.json` — список согласований.

**Расширенные возможности Python (по программе ПР2):**
- `lambda`-функция в `sort_documents_by_deadline()` для ключа
  сортировки;
- генераторы списков для поиска и фильтрации;
- документирующие строки (docstring) для всех функций;
- аннотации типов основных функций (`Dict[int, dict]`,
  `List[dict]`, `Tuple[bool, str]` и т.д.).

**Тестирование pytest:**
- каталог `tests/` создан;
- 7 автоматизированных тестов в `tests/test_approvals.py`:
  добавление, поиск, статус, согласование, правило автора, создание и
  отмена согласования;
- все тесты успешно проходят.

**Качество кода:**
- `requirements.txt` фиксирует версии `pytest>=8.0` и `flake8>=7.0`;
- `setup.cfg` настраивает `flake8` (max-line-length=79);
- код проверен `flake8` без замечаний.

## Этап PR3 — объектно-ориентированная модель

**Тег в Git:** `pr3` (коммит `ea83cf2`).

Функциональная модель ПР2 переработана в объектно-ориентированную.
Основные сущности предметной области представлены классами, данные и
поведение объединены в объектах.

### Что добавлено — пакет `models/`

Создан пакет `models/` с тремя классами:

#### Класс `Document` (`models/documents.py`)

Атрибуты:
- `id` — идентификатор документа;
- `title` — название;
- `doc_type` — тип документа;
- `author_id` — идентификатор автора;
- `deadline` — срок согласования (`date`).

Методы:
- `is_overdue(current_date)` — проверка истечения срока;
- `get_status(approvals)` — определение кода статуса документа по
  согласованиям;
- `get_status_label(approvals)` — текстовое представление статуса;
- `__str__()` — строковое представление документа;
- `from_data(data)` — создание объекта из словаря (`@classmethod`);
- `to_dict()` — преобразование в словарь для JSON;
- `validate_title(title)` — проверка названия (`@staticmethod`).

#### Класс `User` (`models/users.py`)

Атрибуты:
- `id`, `name`, `department`, `role`, `email`.

Методы:
- `__str__()` — строковое представление;
- `from_data(data)` — создание из словаря (`@classmethod`);
- `to_dict()` — преобразование в словарь.

#### Класс `Approval` (`models/approvals.py`)

Атрибуты:
- `id` — идентификатор согласования;
- `document_id` — идентификатор документа;
- `user_id` — идентификатор согласующего;
- `decision` — решение («approved», «rejected», «pending»);
- `comment` — комментарий согласующего;
- `approval_date` — дата (`date` или `None`);
- `is_cancelled` — признак отмены.

Методы:
- `cancel()` — отменить согласование (меняет флаг `is_cancelled`);
- `__str__()` — строковое представление;
- `from_data(data)` — создание из словаря (`@classmethod`);
- `to_dict()` — преобразование в словарь.

### Принципы ООП, продемонстрированные в проекте

- **Инкапсуляция:** данные сущности и связанные с ней операции
  объединены в одном классе. `Document` хранит срок согласования и сам
  умеет проверять его истечение через `is_overdue()`.
- **Полиморфизм:** метод `__str__()` реализован в каждом классе и
  возвращает подходящее представление объекта. `print(document)`,
  `print(user)`, `print(approval)` работают единообразно.
- **Композиция:** согласование `Approval` хранит идентификаторы
  связанных документа и пользователя. В JSON это `document_id` и
  `user_id`. При загрузке связи восстанавливаются — методы
  `find_document_in_list()` и `find_user_in_list()` находят
  соответствующие объекты. Это типичная композиция: `Approval` использует
  `Document` и `User`, не являясь ими.

### Декораторы, использованные в проекте

| Декоратор | Где применяется | Зачем |
|---|---|---|
| `@classmethod` | `Document.from_data()`, `User.from_data()`, `Approval.from_data()` | Создание объекта через сам класс `cls`, что позволяет создавать объекты из данных JSON. |
| `@staticmethod` | `Document.validate_title()` | Проверка корректности названия без обращения к данным конкретного объекта. |

### Адаптация функций ПР2

Функции ПР2 не удалены, а переработаны под объектную модель. Изменения:

| Функция ПР2 | Что изменилось в ПР3 |
|---|---|
| `add_document()` | Создаёт объект `Document` и добавляет его в `List[Document]`. |
| `find_document()` | Принимает `List[Document]`, возвращает `List[Document]`. |
| `find_document_by_id()` | Принимает `List[Document]`, возвращает `Optional[Document]`. |
| `sort_documents_by_deadline()` | Сортирует коллекцию объектов `Document` через `lambda`. |
| `show_documents()` | Принимает `List[Document]` и `List[Approval]`. Использует метод `document.get_status_label()`. |
| `add_user()`, `find_user()`, `show_users()` | Работают с `List[User]` вместо `dict[int, dict]`. |
| `can_approve_document()` | Принимает объекты `Document` и `User`. |
| `create_approval()` | Принимает объекты `Document` и `User`, возвращает `Optional[Approval]`. |
| `cancel_approval()` | Находит согласование и вызывает его метод `cancel()`. |
| `get_approval_status()` | Использует метод `document.get_status_label(approvals)`. |

Функции, оставшиеся обычными функциями:
- `input_int()`, `input_date()`, `input_str()` — общий ввод, не
  относятся к конкретной сущности;
- `load_documents()`, `save_documents()`, `load_users()`, `save_users()`,
  `load_approvals()`, `save_approvals()` — работа с внешним хранилищем
  JSON, а не поведение отдельного объекта.

### Хранение объектов в JSON

Принцип хранения данных:
- JSON-файлы не содержат внутренней структуры Python-объектов — только
  данные, позволяющие восстановить объекты при следующем запуске.
- `Document` и `User` сохраняют все свои атрибуты.
- `Approval` вместо ссылок на объекты `Document` и `User` хранит их
  идентификаторы (`document_id`, `user_id`).

При загрузке:
1. Загружаются документы → `List[Document]`.
2. Загружаются пользователи → `List[User]`.
3. Для каждого согласования из `approvals.json`:
   - по `document_id` находится объект `Document`;
   - по `user_id` находится объект `User`;
   - создаётся объект `Approval` с восстановленными связями.

При сохранении объекты преобразуются в словари методом `to_dict()`.

### Адаптация тестов pytest

Тесты ПР2 (`tests/test_approvals.py`) переработаны и расширены:
- `tests/test_documents.py` — 12 тестов класса `Document` и функций
  работы с коллекцией документов;
- `tests/test_users.py` — 7 тестов класса `User` и функций
  пользователей;
- `tests/test_approvals.py` — 12 тестов класса `Approval` и функций
  согласований, включая проверку правил доступности документа.

Всего: 31 тест, все успешно проходят.

Тесты проверяют:
- создание объектов и значения атрибутов;
- методы классов (`is_overdue()`, `get_status()`, `get_status_label()`,
  `cancel()`, `__str__()`);
- `@classmethod from_data()` и `to_dict()` — корректность
  преобразования в JSON и обратно;
- `@staticmethod validate_title()`;
- правила доступности документа:
  - автор не может согласовать собственный документ;
  - нельзя создать два активных согласования одного документа;
  - отменённое согласование разблокирует документ;
  - документ с истёкшим сроком нельзя согласовать;
- отмену согласования по идентификатору;
- поиск согласования по идентификатору.

## Что за что отвечает

### `main.py`
Точка входа в приложение. Отвечает за:
- запуск приложения;
- отображение главного меню;
- получение данных от пользователя через `utils.input_*`;
- организацию пользовательских сценариев через 12 функций
  `*_menu()`;
- загрузку данных через `storage.load_*`;
- сохранение данных через `storage.save_*` перед завершением.

### `models/documents.py`
Содержит класс `Document` и функции работы с коллекцией документов:
- класс: `Document` (атрибуты + методы + `@classmethod from_data` +
  `@staticmethod validate_title`);
- функции: `add_document()`, `find_document()`, `find_document_by_id()`,
  `filter_documents_by_type()`, `sort_documents_by_deadline()`,
  `show_documents()`, `_next_document_id()`.

### `models/users.py`
Содержит класс `User` и функции работы с пользователями:
- класс: `User`;
- функции: `add_user()`, `find_user()`, `find_user_by_id()`,
  `show_users()`, `_next_user_id()`.

### `models/approvals.py`
Содержит класс `Approval` и функции согласований:
- класс: `Approval`;
- функции: `can_approve_document()`, `is_document_open_for_approval()`,
  `create_approval()`, `cancel_approval()`, `find_approval_by_id()`,
  `get_approval_status()`, `show_approvals()`, `find_document_in_list()`,
  `find_user_in_list()`, `_next_approval_id()`.

### `storage.py`
Отвечает за загрузку и сохранение данных. Выполняет преобразование:
- JSON → объекты Python (`Document.from_data()`, `User.from_data()`,
  `Approval.from_data()`);
- объекты Python → JSON (`to_dict()`).

Обрабатывает исключения `FileNotFoundError` и `JSONDecodeError`.

### `utils.py`
Содержит вспомогательные функции безопасного ввода:
- `input_int(prompt)` — безопасный ввод целого числа (ловит
  `ValueError`);
- `input_date(prompt)` — безопасный ввод даты в формате `ДД.ММ.ГГГГ`;
- `input_str(prompt)` — безопасный ввод непустой строки.

### `tests/`
Содержит автоматизированные тесты pytest. 31 тест в трёх файлах,
все проходят.

### `data/`
Содержит JSON-файлы с подготовленными данными:
- 3 документа (договор, акт, служебная записка);
- 3 пользователя (Иванов, Петров, Сидорова);
- 1 согласование (документ №1, согласованный Петровым).

### `requirements.txt`
Фиксирует инструменты разработки: `pytest>=8.0`, `flake8>=7.0`.

### `setup.cfg`
Настраивает `flake8`: максимальная длина строки 79 символов, исключения
для служебных каталогов (`__pycache__`, `.venv`, `.pytest_cache`).

### `.gitignore`
Исключает из Git: виртуальные окружения, кэш Python, настройки IDE,
временные файлы.

## Как запустить и проверить

### Установка зависимостей

```bash
cd document_approval
pip install -r requirements.txt
```

### Запуск программы

```bash
python main.py
```

Откроется меню:

```
=== Система согласования документов ===

--- Главное меню ---
1. Показать документы
2. Найти документ по названию
3. Отсортировать документы по сроку
4. Показать пользователей
5. Найти пользователя
6. Добавить документ
7. Добавить пользователя
8. Проверить возможность согласования
9. Создать согласование
10. Отменить согласование
11. Показать согласования
12. Показать статус документа
0. Выход
```

### Запуск тестов

```bash
pytest -v
```

Ожидаемый результат: `31 passed`.

### Проверка качества кода

```bash
flake8 .
```

Ожидаемый результат: нет замечаний (команда не выводит ничего).

### Просмотр истории Git

```bash
git log --oneline
git tag -l
```

Ожидаемый результат: 3 коммита (PR1, PR2, PR3) и 3 тега (`pr1`, `pr2`,
`pr3`).
